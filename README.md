# Deep Neural Networks for Estimating the m-Height of Analog Error-Correcting Codes

Course project for **CSCE 636: Deep Learning**, Texas A&M University.

## Problem

Analog codes are real-valued error-correcting codes generated by a full-rank matrix `G = [I | P]`. A key property used to analyze their error-correction performance is the **m-height** of the code — informally, the worst-case ratio between the largest-magnitude and m-th-largest-magnitude entries across all codewords. Computing the exact m-height requires solving a large number of linear programs (LPs), which becomes expensive as the code parameters `(n, k, m)` grow.

This project trains deep neural networks to **estimate** the m-height directly from a code's generator matrix, bypassing the LP-based computation at inference time.

**Input:** integers `n`, `k`, `m`, and a `k × (n − k)` matrix `P` (the non-identity part of the systematic generator matrix).
**Output:** a predicted m-height (a real number ≥ 1).

The project covers 21 parameter configurations: `n ∈ {9, 10}`, `k ∈ {4, 5, 6}`, `m ∈ {2, ..., n − k}`.

## Approach

**1. Dataset generation.** Training labels were generated using an LP-based algorithm (based on Jiang, "Analog Error-Correcting Codes: Designs and Analysis" — see [Reference](#reference) below) that computes the exact m-height for a given generator matrix. Datasets of up to ~915,000 labeled samples were generated per `(n, k, m)` configuration, split 70/15/15 into train/validation/test sets.

**2. Baseline regression models.** A dense neural network was trained per configuration to directly regress the m-height value.

**3. Diagnosing failure cases.** Six of the 21 configurations exhibited severe right-skew — m-height values spanning up to 7 orders of magnitude — which caused standard regression to perform poorly under a log-scale loss (log-loss 7.5–9.6 on these configs, versus <1.1 on the rest).

**4. Reformulation as classification.** For these six configurations, the problem was reframed as multi-class classification: m-height values were bucketed into logarithmically spaced bins (10 bins per decade — 1–10, 10–100, 100–1,000, etc.), and a network was trained to predict bin membership via `sparse_categorical_crossentropy`. This directly optimizes for the log-scale evaluation metric instead of penalizing large absolute errors that dominate under skewed data.

**5. Hybrid inference.** A single prediction function (`DNN_for_m_height`) routes each input to the appropriate model — regression or log-binned classification — based on its `(n, k, m)` configuration, so the caller doesn't need to know which approach was used internally.

## Model Architecture

- 5 fully connected hidden layers, 128 units each, ReLU activation, with dropout (0.2) between layers
- Output layer:
  - Regression configs: single linear unit
  - Classification configs: softmax over log-spaced bins
- Optimizer: Adam (learning rate 1e-5)
- Loss: MSE (regression) / sparse categorical cross-entropy (classification)
- Trained for 20 epochs per configuration, with best-checkpoint selection on validation loss

## Evaluation Metric

Predictions are scored on a log-scale squared error:

```
loss(y, ŷ) = (log2(y) − log2(ŷ))²
```

which penalizes multiplicative rather than additive error — appropriate given the multi-order-of-magnitude range of m-height values.

## Results

| Configuration | Regression-only log-loss | Final (hybrid) log-loss |
|---|---|---|
| n=9, k=4, m=5  | 7.830 | 3.829 |
| n=9, k=5, m=4  | 9.035 | 3.913 |
| n=9, k=6, m=3  | 9.607 | 3.857 |
| n=10, k=4, m=6 | 7.461 | 4.488 |
| n=10, k=5, m=5 | 9.627 | 6.339 |
| n=10, k=6, m=4 | 8.565 | 6.309 |

**Overall weighted log-loss across all 21 configurations: 1.848** (down from 3.139 for the regression-only baseline) — a ~41% reduction.

The remaining error on the two hardest configurations (`n=10,k=5,m=5` and `n=10,k=6,m=4`) reflects their especially wide dynamic range; even log-binned classification has coarser effective resolution at the extreme tails. Finer-grained binning or a mixture density network are natural next steps.

## Running the Notebook

The notebook is designed to run in Google Colab. It expects a pre-generated dataset (see Dataset Generation section in the notebook) and will:
1. Load and preprocess the data per `(n, k, m)` configuration
2. Train the regression or classification model as appropriate
3. Report training/validation curves and final test log-loss
4. Expose a single callable `DNN_for_m_height(n, k, m, p_list)` for inference on new inputs
